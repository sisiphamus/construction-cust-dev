# Civil Engineer A (small Texas civil firm partner) - built an internal ops system with Claude Code

## Main themes

- **Build for buy-in.** Philosophy: do something once fine, twice find a better way, never a third time slow. He takes almost every team suggestion (even dark mode) because once someone's idea ships they take ownership and start "dreaming about" the system. Never shoot down suggestions or people go into a shell.
- **From workflow automation to Claude Code.** He ran firm automations on a Microsoft low-code automation tool for ~7 years (email parsing, job-number matching, filing). His "aha" was a 25-minute Claude Code session that printed, renamed and reordered 500 invoice emails to PDF, including a Python script so it would not burn tokens. He now runs a unified internal ops system.
- **The buried-spreadsheet wedge.** His sharpest line: the value is the spreadsheet buried somewhere that only one person knows about. Automate that and you have something. He cited an AI-savvy peer whose pipeline-materials project drove ~30% more profit in a quarter by solving one person's job.
- **Every company's ops are bespoke, so generic SaaS fails.** Over ~10 years he tried Monday.com, Jira-like tools, "all of them"; none tracked granularity like "take out the trash," which he insists on so the team feels their work matters. He doubts a one-size tool can be sold unless you first listen inside a company for a month.
- **Vertical integration / own the data layer.** When Interviewer 2 described sitting on top of point tools (lead-gen, inbox cleanup, AI-search optimization) and packaging them for the average user, he pushed toward owning the data-entry layer: if you build the system people already type into, you own the metadata of every transaction (grocery-loyalty-card analogy) and can match demand to supply across the trades.
- **Voice / podcast shift.** He built a feature that auto-writes a daily project brief (a few cents) and converts it to an audio "podcast" he listens to each morning (~17-20 cents). He thinks it could be sold but it is only as good as the data fed in.
- **Generational build instinct.** Long-time builder, sees the interviewer as an outlier of his generation for actually building; stakes are low while young; most good ideas come out of conversations.
- **Interviewer's setup (show-and-tell).** A shared notes vault with a shared company layer in version control plus private per-person folders; keep the CLAUDE.md instruction file lean (under ~150 lines) because it loads every session; run an audit against a reference file.

## Representative quotes

- "The value in all of this is that spreadsheet that's buried somewhere that only one person knows about. You go automate that, now you got something."
- "If you do something once, I'm fine. If I do something twice, I'm finding a better way to do it. But I'm not doing it a third time slow."
- On the metadata play: "It's really the metadata of that transaction that's valuable... the reason [grocers] give you the discount for using their card is they know everything about you. Do that for construction."
- Interviewer 2: "No matter what happens with AI, people want more customers. That's not gonna change."
